# WOLF Console 1.6 · I²C → ESP32-S3 N16R8 → Wi-Fi / TCI

В комплекте прошивка ESP32, автономный пульт для компьютера с оформлением версии 1.5 и исходники обеих частей. «Волк» остаётся на штатной прошивке STM32 16.5.1. Для частоты, режимов, S-метра, карты диапазона и управления нужны только три провода между устройствами. Компьютер соединяется по Wi-Fi.

Исправление сборки Arduino: входные команды TCI декодируются в Tci.cpp без вызова base64::decode. Образы в firmware пересобраны с этим исправлением.

## Установка на действующую консоль 1.5

1. Распакуйте весь ZIP. В прежней веб-панели переведите трансивер на приём. Откройте **Настройки → Обновление прошивки ESP32** и выберите **firmware/WOLF_YD_N16R8_1_6_OTA.bin**. Дождитесь перезапуска. При обновлении по воздуху сохраняются записанные настройки сети, портов и аудиовхода.
2. Оставьте рабочую разводку I²C. В WOLF должны быть включены **TRX Settings → Wolf Interface I2C** и **Calibration Control → CAT Type → TS-2000**. Для новой установки сверяйтесь с таблицей ниже.
3. Подключите компьютер к своей обычной сети с ESP32 или к **WOLF-Console**. Начальный пароль точки — **WolfPanel-1651**. Начальный адрес в этой сети — **192.168.4.1**. Для домашней сети возьмите адрес из настроек платы.
4. Запустите программу для своей системы. При первом запуске введите IP ESP32 и нажмите **Открыть пульт**. Сменить адрес впоследствии можно в **Станция → Адрес ESP32**. Программа запоминает адрес и восстанавливает связь.
5. В USB, LSB или CW дождитесь **I²C на связи**, **TS-2000** и числового показания RX1. Измените частоту, остановитесь до следующего показания RX1, затем перестройтесь ещё раз. В окне карты должны появиться точки на посещённых частотах. Так можно проверить весь тракт на приёме.

| ESP32-S3, исходная конфигурация | WOLF, разъём программатора STM32 |
|---|---|
| GPIO5 · SDA | SWO |
| GPIO18 · SCL | SWDIO |
| GND | GND |

Подключайте при снятом питании. В исходном проекте используются линии с подтяжками к 3,3 В. «Волк» задаёт тактирование, адрес ведомой ESP32 — 0x76. Номера выводов могут отличаться, если вы уже меняли их в настройках панели. Для работы достаточно отдельного питания ESP32 и общей земли. Программатор STM32 освободите от этих линий.

## Настольная программа

| Система | Первый запуск из комплекта | Повторная сборка из исходников |
|---|---|---|
| Windows 10–11 x64 | Запустите **Windows/WolfConsole-1.6.0-x64.exe**. Это переносимая программа. | **desktop/build-windows.cmd** |
| macOS 12 и новее, Apple M1/arm64 | Откройте **macOS/create-DMG.command**. Рядом появится **WolfConsole-1.6.0-arm64.dmg**. Откройте DMG и перетащите WOLF Console в Applications. | **desktop/build-mac-m1.command** |

Оба варианта первого запуска используют готовую программу из ZIP и работают без Node.js, интернета, внешнего браузера и промежуточного TCI-сервера. Оставьте каталоги проекта рядом друг с другом. Если после распаковки Finder не запускает командный файл, откройте Terminal в каталоге проекта и выполните:

```sh
bash macOS/create-DMG.command
```

Скрипт распаковывает arm64-приложение, ставит локальную ad-hoc подпись, проверяет её и создаёт образ штатной утилитой hdiutil. Для этого не нужен аккаунт Apple Developer. Комплект предназначен для локальной установки. Разрешите доступ к локальной сети, если его запросит macOS.

Для **пересборки после правок** установите Node.js 22 LTS для своей платформы и запустите скрипт из правой колонки. Он получает зависимости по package-lock.json, собирает программу и открывает папку результата **desktop/dist**. Этот способ требует интернета при первой сборке. Для запуска исходников разработчиком — `npm ci` и `npm start` в папке desktop. Основной интерфейс общий для настольной программы и веб-пульта. После правок Panel.h, PanPage.h, TciPage.h или Player.h обновите локальные ресурсы командой `node tools/sync-ui.cjs` из корня проекта перед сборкой настольной программы.

## Что показывает окно карты

Штатный Wolf Interface I²C возвращает частоты, режимы, состояние RX/TX, ответы CAT и уровень RX1. **Измерение относится к полосе фильтра настроенного приёмника.** Пульт отмечает его в dBm на частоте активного VFO. Он ждёт нового замера после перестройки. Если частота или режим изменились в промежутке между запросом и ответом CAT, этот замер пропускается. На непрослушанных частотах поле пустое.

Ширина видимой шкалы выбирается из 12, 48 и 96 кГц. В памяти окна остаётся до 1024 последних частот за три минуты. Текущая частота отмечена светло-зелёным. Карта очищается при смене VFO, режима, переходе на передачу или потере связи. Позывные скиммера добавляются, только если соответствующий сетевой источник настроен. Пульт сам не перестраивает приёмник для заполнения карты.

**Широкополосный спектр и водопад одновременно по всей полосе требуют I/Q. Штатный WOLF 16.5.1 таких отсчётов в Wolf Interface I²C не выдаёт.** USB-кабель от WOLF и отдельный файл WOLF-IQ.html для этой версии не нужны.

В DIGL/DIGU сохраняется окно FT8/FT4. На трёх проводах нет звука для воспроизведения или локального декодирования. Если аудиовход был подключён в прежней установке, выберите или проверьте его в **Настройки → Звук и цифровой приём ESP32**. Явно сохранённые настройки продолжают действовать. При отсутствии сохранённой настройки захват по умолчанию выключен. Подробности о декодере, источнике WSJT-X и дополнительных возможностях приведены в файле **Дополнительные_настройки.md**.

## TCI и проверка связи

ESP32 принимает клиентские соединения WebSocket на **ws://192.168.4.1:50001** в сети точки доступа. В домашней сети замените IP на адрес платы. Одновременно доступно до пяти TCI-подключений. Программа получает состояние по подписке. Результат команды настройки подтверждается следующим состоянием от трансивера.

| Назначение | Реализованные сообщения |
|---|---|
| Начало сеанса | protocol, device, trx_count, channel_count, receive_only, vfo_limits, modulations_list, start/stop по состоянию связи, ready |
| Частота и режим | vfo (приёмник 0, канал 0 = A, 1 = B), dds (частота активного VFO), modulation |
| Управление | split_enable, drive, trx, tune |
| Измерения | rx_sensors_enable и rx_sensors для фактических измерений RX1 |
| Функции пульта WOLF | wolf_panel и wolf_state для полного снимка, wolf_id / wolf_ack для квитанций, wolf_cmd для кнопок CAT, wolf_hold для удержания PTT/TUNE |

Это подмножество TCI для управления. Бинарные потоки IQ и аудио по TCI в этой конфигурации отсутствуют. В сообщениях используется нумерация команд TCI 1.8. Подробности стандартного протокола опубликованы в репозитории [Expert Electronics](https://github.com/ExpertSDR3/TCI). Описание штатного I²C с исходным примером опубликовано в [проекте WOLF 16.5.1](https://github.com/XGudron/UA3REO-DDC-Transceiver/tree/16.5.1/Stuff/Wolf-Interface).

В примере `vfo:0,0;` запрашивает частоту A, `vfo:0,1;` — частоту B, `rx_sensors_enable:true,250;` подписывается на свежие измерения RX1. Обычные текстовые команды завершаются точкой с запятой. Для стороннего TCI-клиента начните с чтения частоты. Штатные кнопки PTT и TUNE в приложении действуют при удержании. Пульт запрашивает RX при отпускании, потере фокуса и разрыве соединения. У прошивки также есть самостоятельный таймер удержания.

Если показано **«Нет связи TCI»**, проверьте IP, сеть и TCP 50001. Если показано **«I²C ожидание»**, компьютер уже связан с ESP32 — проверьте Wolf Interface и линии SDA/SCL. Если обновляются частоты, а на карте пусто, проверьте режим приёма, **TS-2000**, **RX1** и счётчики CAT. Веб-пульт и настройки ESP32 доступны на HTTP-порту 80. Через него же работают необязательные журнал и споты; прежний поток прослушивания с АЦП использует порт 81.

## Новая плата или сборка скетча

Для новой ESP32-S3 **N16R8** в каталоге firmware находится полный образ **WOLF_YD_N16R8_1_6_USB_full.bin**. Он записывается с адреса 0x0 и заменяет начальную область flash, в том числе прежние настройки. Для работающей версии 1.5 используйте OTA-образ из первого раздела. Примеры для esptool 5.x — подставьте порт своей ESP32:

```powershell
py -m esptool --chip esp32s3 --port COM5 --baud 460800 write-flash 0x0 firmware/WOLF_YD_N16R8_1_6_USB_full.bin
```

```sh
python3 -m esptool --chip esp32s3 --port /dev/cu.usbmodemXXXX --baud 460800 write-flash 0x0 firmware/WOLF_YD_N16R8_1_6_USB_full.bin
```

Для Arduino IDE установите пакет **esp32 by Espressif Systems 3.3.13**. Библиотека **WebSockets 2.7.1** включена в libraries/WebSockets. Скопируйте её в каталог libraries вашего скетчбука или установите ту же версию из менеджера библиотек. Откройте WolfConsole/WolfConsole.ino. Профиль — ESP32S3 Dev Module, Flash 16 MB, QIO 80 MHz, OPI PSRAM, раздел 16M Flash (3MB APP/9.9MB FATFS), Hardware CDC and JTAG, USB CDC On Boot Enabled. Команда из корня проекта использует включённую в архив библиотеку:

```sh
arduino-cli compile --fqbn "esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,FlashMode=qio,PartitionScheme=app3M_fat9M_16MB,CDCOnBoot=cdc" --libraries libraries WolfConsole
```

## Проверки версии 1.6

Прошивка собрана для ESP32-S3. Проверены контрольная сумма приложения, его вхождение в полный образ и маркер семейства для OTA из версии 1.5. На программной модели проверены реальные обработчики I²C-кадров и TCI, чтение и установка частоты, мода, подписка на RX1, отбрасывание замера после перестройки и снятие PTT при обрыве. Отдельное окно Electron прошло проверку на имитаторе сетевой станции с вводом частоты, сменой VFO и антенны, DIGU/USB, картой, удержанием PTT и переподключением. Собраны пакеты приложения arm64 для macOS и x64 для Windows. Проверка физической шины, приёма и установки на целевых компьютерах остаётся за испытанием на станции.
